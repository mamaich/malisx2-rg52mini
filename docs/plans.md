# Планы

Порядок — по приоритетам форка: сначала падения, потом скорость.

## Ближайшее

1. **Опыты с батчами**: `MALISX2_JM_BATCH_PASSES` = 16/4/2/1 и
   `MALISX2_JM_HEAP_SLOTS` = 4/8 на ARMSX2 — перекрытие слотов, простой GPU,
   ожидания номеров атомов, память. Ручки уже есть (`362589c`).
2. **Uniform-слова в FAU без заданий копирования.** После шага 0 это самая
   большая часть оставшихся compute-заданий: на God of War 0,70 (VS) + 0,65
   (FS) на отрисовку против 0,78 копий дескрипторов. Вариант — писать слова
   на CPU при записи команд, когда данные динамического UBO уже в памяти
   (как у ARMSX2: он пишет константы в потоковый буфер перед отрисовкой), или
   читать их в шейдере из UBO, когда блок пересобирается слишком часто.
3. **Другие игры GameCube** на malisx2 — искать падения, как у ND Demo.
4. **Остальные эмуляторы dArkOS** с выбором Vulkan-драйвера: PPSSPP,
   DuckStation/SwanStation, Flycast, порты. Сначала — запускаются ли без
   падений, потом скорость против libmali.

## Скорость отрисовки на v7, следующие шаги

Исходная картина (Castlevania, 3DS, трасса слотов kbase, мс на кадр; замер
сессии dArkOS 25.10.2026):

| | libmali | malisx2 |
|---|---|---|
| кадр | 50,1 | 64,0 |
| вершины, тайлер, compute | 12,6 | 25,5 |
| фрагменты | 33,5 | 37,1 |
| оба слота одновременно | 6,1 | 1,1 |
| GPU простаивает | 10,0 | 2,5 |

Причины: нет IDVS (вершинное задание пишет в память все varyings), около
2,7 compute-заданий на отрисовку (копии дескрипторов и uniform-слов), мало
перекрытия вершин следующего прохода с фрагментами текущего. «Шаг 0»
(26.10.2026) снял на God of War 16 % копий, на Jak and Daxter — 7 %
([changes.md](changes.md)). Дальше, по мере результатов замеров:

- uniform-слова в FAU без заданий копирования (см. «Ближайшее»);
- таблицы дескрипторов, собранные на CPU при записи команд, вместо
  compute-копий на GPU;
- IDVS на v7: шейдинг только вершин из индексов и без записи всех varyings;
  после него можно будет снять проверку границ SSBO из `80994d9`;
- атомы на каждый проход, больше перекрытия слотов;
- CRC (transaction elimination) на job manager.

## Позже

- **Настоящие occlusion-запросы** — когда попадётся игра или эмулятор, которым
  нужен реальный счёт. План реализации — в комментарии в начале
  `src/vk/mali_jm_query.c`, оценка — 3–4 часа; `vkCmdCopyQueryPoolResults` —
  ещё 1–2 часа.
- Держать форк в синхроне с апстримом (merge в `main`).
- После изменений компилятора шейдеров или горячего пути отрисовки —
  снимать профиль PGO заново ([building.md](building.md)).
