## Скорость отрисовки на v7, следующие шаги

Исходная картина (Castlevania, 3DS, трасса слотов kbase, мс на кадр; замер
сессии dArkOS 25.10.2026):

| | libmali | malisx2 |
|---|---|---|
| кадр | 50,1 | 64,0 |
| вершины, тайлер, compute | 12,6 | 25,5 |
| фрагменты | 33,5 | 37,1 |
| оба слота одновременно | 6,1 | 1,1 |
| GPU простаивает | 10,0 | 2,5 |

Причины: нет IDVS (вершинное задание пишет в память все varyings), около
2,7 compute-заданий на отрисовку (копии дескрипторов и uniform-слов), мало
перекрытия вершин следующего прохода с фрагментами текущего. «Шаг 0»
(26.10.2026) снял на God of War 16 % копий, на Jak and Daxter — 7 %
([changes.md](changes.md)). Дальше, по мере результатов замеров:

- uniform-слова и таблицы дескрипторов на CPU — сделано 27.10.2026
  (`0153cde`, `9ca29fd`), заданий вдвое меньше, но fps на ARMSX2 тот же:
  время GPU — фрагменты, см. [hardware.md](hardware.md);
- код шейдеров Bifrost (см. «Ближайшее»); AFBC для текстур — сделано
  27.10.2026;
- IDVS на v7: шейдинг только вершин из индексов и без записи всех varyings;
  после него можно будет снять проверку границ SSBO из `80994d9`. Jak and
  Daxter в игре упирается в поток GS, и запись отрисовок
  (`CmdDrawIndexed`, два задания на отрисовку) — около 14 % его времени;
  с IDVS задание было бы одно;
- запись и повтор трасс Vulkan (gfxreconstruct) — A/B без эмулятора, без
  разброса между раундами;
- `MALISX2_DEBUG=perf`: сообщения в лог, когда драйвер выбирает медленный путь
  (как `TU_DEBUG=perf` у Turnip);
- атомы на каждый проход, больше перекрытия слотов;
- CRC (transaction elimination) на job manager.
