# Планы

Порядок — по приоритетам форка: сначала падения, потом скорость.

## Ближайшее

1. **«Шаг 0» скорости на v7** — дешёвые правки, каждая отдельным коммитом,
   чтобы мерить вклад каждой; в работе, в форк — после замеров на
   устройстве:
   - счётчики в логе (`MALISX2_STATS`): атомы, ожидания номеров атомов,
     задания на отрисовку, копии дескрипторов и uniform-слов по стадиям;
   - FAU-блок стадии не пересобирать, когда пересобраны только её таблицы,
     а шейдер и динамические UBO те же;
   - при проверке, можно ли оставить таблицы стадии, сравнивать только
     сеты, которые шейдер читает;
   - `vkCmdPushConstants` — помечать FAU только стадий из `stageFlags`
     (ARMSX2 перед каждой отрисовкой с развёрткой задаёт base vertex только
     для вершинного шейдера);
   - push-сет с теми же байтами, что в его последнем блоке, — тот же блок;
   - ручки числа проходов в батче и слотов кучи тайлера для опытов с
     перекрытием слотов GPU.

   Замеры: счётчики по шагам на God of War и Jak and Daxter (ARMSX2); время
   кадра (среднее, p95, p99 по флипам) — исходная версия против итоговой,
   обе собраны как в образе (LTO + PGO); опыты с батчами — перекрытие
   слотов, простой GPU, ожидания номеров атомов, память.
2. **Цена проверки границ SSBO** в вершинных шейдерах (`80994d9`) для
   ARMSX2 — по тем же замерам.
3. **Другие игры GameCube** на malisx2 — искать падения, как у ND Demo.
4. **Остальные эмуляторы dArkOS** с выбором Vulkan-драйвера: PPSSPP,
   DuckStation/SwanStation, Flycast, порты. Сначала — запускаются ли без
   падений, потом скорость против libmali.

## Скорость отрисовки на v7, следующие шаги

Исходная картина (Castlevania, 3DS, трасса слотов kbase, мс на кадр; замер
сессии dArkOS 25.10.2026):

| | libmali | malisx2 |
|---|---|---|
| кадр | 50,1 | 64,0 |
| вершины, тайлер, compute | 12,6 | 25,5 |
| фрагменты | 33,5 | 37,1 |
| оба слота одновременно | 6,1 | 1,1 |
| GPU простаивает | 10,0 | 2,5 |

Причины: нет IDVS (вершинное задание пишет в память все varyings), около
2,7 compute-заданий на отрисовку (копии дескрипторов и uniform-слов), мало
перекрытия вершин следующего прохода с фрагментами текущего. Шаги после
«шага 0», по мере результатов замеров:

- таблицы дескрипторов, собранные на CPU при записи команд, вместо
  compute-копий на GPU;
- uniform-слова в FAU без заданий копирования;
- IDVS на v7: шейдинг только вершин из индексов и без записи всех varyings;
  после него можно будет снять проверку границ SSBO из `80994d9`;
- атомы на каждый проход, больше перекрытия слотов;
- CRC (transaction elimination) на job manager.
